# In Line｜排着呢

In Line 是一款通用的 Windows 本地取号与事项队列工具。它适合个人或内部支持岗位记录任务、展示排队顺序、发送取号卡片，适合业务量较大的职能部门使用。

当前开发版本：`v0.2.2`（2026-08-27）。完整变更见 [CHANGELOG.md](CHANGELOG.md)。

## 主要功能

- **事项登记**：登记事项后自动编号，支持部门/团队、多人对接、事项类型、优先级、状态和截止时间。
- **队列管理**：支持人工调序、加急、逾期优先、暂缓管理，以及已处理、已完成事项重新加入今日队列。
- **取号卡片**：快捷生成高清竖版 PNG，展示号码、事项信息、当前状态和前方待处理数量，可直接复制发送对接人。
- **办理记录**：记录每次办理活动和状态变化，支持已处理、完成、暂缓、归档、回收站恢复及重复事项合并。
- **工作日历**：支持周视图和月视图查看每日实际办理情况；周视图通过轻量甘特展示事项每次加入队列至本轮处理结束的时间区间，可直观看到同一事项的多轮处理轨迹。
- **筛选查找**：待办队列、历史归档和回收站可按部门、对接人、类型、状态及截止时间筛选。
- **统计分析**：支持按时间范围查看事项处理结果、完成率、事项类型、工作量趋势及周期/团队对比。统计中心图表可以排序、隐藏和恢复；事项类型支持列表、饼状图及明细展开。
- **工作报告**：可通过本地 MCP 访问指定日期范围的统计和办理记录，生成日报、周报、月报或年报。支持按工作复盘、精简汇报、事项分类或自定义模板生成报告指令。
- **数据备份**：支持自动备份、外部备份导入、非破坏性合并、事项类型归并和冲突事项人工复核。
- **隐私保护**：In Line 软件本身无需联网，启用 MCP 功能时不监听网络端口且不能修改事项，也不会返回联系人、事项详情、内部备注和回收站内容，确保数据安全。

## 数据兼容与位置

v0.2.2 继续使用原有数据位置：

`%APPDATA%\in-line\inline.db`

首次迁移旧数据库时，会先在 `backups` 目录生成 `InLine-backup-日期时间-before-migration.db`。旧格式备份会在启动时统一整理名称。应用更新或卸载不会主动删除用户数据库。

软件设置中的手动备份与每日自动备份会同时保存事项、办理记录和软件设置，包括开机自动启动状态。“可恢复备份”支持导入外部 `.db`、手动刷新，并在页面打开期间自动发现备份目录中新加入的文件。恢复采用非破坏性合并：完全一致的事项合并关联记录，同名但内容不同的导入事项作为冲突副本另行保留，并显示持久的“导入冲突”标识；合并完成后会立即列出冲突事项，方便逐项打开、合并或人工复核。所选备份中的有效软件设置覆盖当前设置并同步 Windows 自启动配置；操作前会自动创建 `before-restore` 应急备份。

合并期间，事项类型会自动去除首尾空格并按不区分大小写的名称归并，避免备份和当前数据产生重复类型。更新或卸载时，安装器会先结束仍被 Codex 等客户端占用的 `in-line-mcp.exe` 伴随进程，再写入新文件；Codex 本身不会被关闭。

无论备份中保存了什么旧显示设置，待办页和悬浮窗都只显示仍有有效队列记录的“待处理”与“处理中”事项；“已处理”、待材料、待确认等进入“暂缓事项”，已完成、已取消和已归档事项进入“历史归档”。

### 从旧版升级

1. 从托盘菜单正常退出旧版 In Line，确认任务管理器中不再有 `In Line.exe`。
2. 如果“设置 → 应用”仍显示 **In Line 0.0.1**，先卸载该 Electron 旧版。卸载不会删除 `%APPDATA%\in-line\inline.db`。
3. 删除或取消固定仍指向旧安装目录的快捷方式。
4. 安装并启动 v0.2.2；程序会沿用现有数据库和设置。
5. 在主界面左下角确认显示 `v0.2.2`，再核对原有事项、号码和日志。

迁移失败时会回滚数据库，不会按新项目清空原有数据。首次升级前仍建议保留一份手动备份。

如果主界面一直停在“正在整理队列”，修复后的程序会显示真实错误和“重新载入”按钮，不再无限等待；悬浮窗的“新增取号”会直接打开主界面的新增表单。

## AI MCP 接入

安装包会在 In Line 主程序旁安装 `in-line-mcp.exe`。该程序采用 stdio 按需启动，不监听网络端口，仅提供以下只读工具：

- `get_report_summary`：读取指定自然日范围内的统计汇总。
- `list_report_items`：分页读取期间内有有效办理记录的事项明细。

“软件设置 → AI MCP 接入”仅保留“通用接入”窗口，内容包含本机启动命令、工具清单和只读权限范围，可直接复制给 Codex 等 AI 客户端并要求其完成配置。统计中心的“生成报告”会自动识别当前区间对应的本周周报、上周周报、月报、季度工作报告或阶段工作报告，并支持工作复盘、精简汇报、事项分类和自定义模板；每个软件版本首次生成时会先提示完成 MCP 接入并选择报告结构。添加配置后需要重启对应客户端。也可以按照 [Codex MCP 官方说明](https://developers.openai.com/codex/mcp/)手动添加该 stdio 程序。

统计中心同时提供数量口径的周期工作量对比和部门 / 团队相关工作量对比。本周与上周同期比较，上一周、上一个月和上一季度分别与前一个完整自然周期比较，自定义范围与紧邻的等长周期比较。对比变化统一采用“红色为增长、绿色为减少”，本周期右侧数值也随增减着色。一个事项归属多个部门时会分别计入各部门，因此部门合计可能高于总事项数。

MCP 只返回事项标题、部门、类型、当前状态、工作量、完成时间和有效办理记录，不提供联系人、事项详情、内部备注、普通操作日志或回收站数据，也不包含任何修改事项的工具。

## 开发

推荐环境：

- Windows 10 / 11 x64
- Node.js 20+
- Rust stable-msvc
- Visual Studio 2022 Build Tools（Desktop development with C++）
- Microsoft Edge WebView2 Runtime

```powershell
npm.cmd install
npm.cmd test
npm.cmd run build
npm.cmd run dist
```

前端为 React + TypeScript + Vite；桌面层为 Tauri 2 + Rust；数据层为 rusqlite + SQLite。

## 安全和隐私

- 纯本地应用，不会上传数据，不包含遥测或第三方统计。
- 前端不能执行任意 SQL，只能调用白名单命令。
- 日志不记录完整事项详情和内部备注。
- 备份恢复前会校验 SQLite 完整性，并自动备份当前数据。
- MCP 使用只读数据库连接，不监听网络端口，并排除联系人、内部备注、事项详情和已删除事项。
