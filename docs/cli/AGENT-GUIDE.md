# In Line CLI：Agent 使用约定

只使用用户在In Line中为当前用途独立授权的CLI profile。按软件生成的一次性提示词接入；长期凭证留在本机，不读出、回显、上传或放入启动参数。CLI与聊天MCP接入分别验证。

## 开始前

1. 使用完整exe路径；先读取版本/帮助，再 `status --profile <实际名称> --format json` 获取有效能力、权限与范围。doctor存在性不等于连接成功。
2. 不存在、被撤销、权限不足或版本不兼容时，保留原错误并交由用户在软件内处理。禁止回退到其他profile、MCP环境变量或更大权限身份。
3. 查询使用JSON，检查退出码及Envelope；每页1–100，不能把一页当成完整集。保存服务端snapshot/cursor或jobId/nextOffset，保持原条件及投影。

## 读写纪律

- 先查询目标与近似重复，多个同名候选向用户消歧。不得猜联系人、截止时间、部门或新义务。常规读取没有自由文本；四字段日报含联系人必须有效fullRead，不静默输出空字段假装完整。
- 写入必须用户明确意图、execute、原幂等键、原因及原版本/字段基准。不得自动制造确认或在冲突后拉新版本覆盖。已达到目标的no_change保留原结果，不编造办理事件。
- 只有真实处理才记录办理。未来取号及排队不算办理；父子完成范围须明确。恢复回收站会加入今日队列，归档重开另用reopen。
- 批量命令固定先预演并由宿主重新核对；软件内整批审批及历史撤销批准不可自动执行或拆单绕过。默认20/硬限100及全部事务/范围规则沿用原服务。
- jobs只运行已有查询/报告/日历/export。取消waiter不等于取消共享job；start/cancel须执行开关，cancel须明确用户指令。未完成/待批准退出8不报成功。
- 备份及导出仅取受控产物引用，不能读取整份备份给AI、接受任意路径或获取其他客户端产物。

## 不明结果

退出9、result_unknown、写入期间authorization_changed、提交后核验失败或发出后断线：保存原key/requestId及已知commitStatus/verificationStatus，停止业务重发。普通写入用 `receipt get --idempotency-key`；产物用同命令加 `--kind artifact`。只读回执不重新执行，也不证明当前状态尚未变化。

命名查询及作业控制没有虚构业务幂等回执：按原name/jobId读取实际状态，不能自动重新启动或猜测已完成。错误诊断限于当前客户端自身errorId，不读取Token、原始业务库、完整日志或任意SQL。

## 向用户报告

明确区分：配置导入、CLI自身连接、当前聊天MCP连接、写入提交、核验、待批准、后台未完成、安装和人工验收。只报告已观察到的事实。完整命令及示例见[用户指南](USER-GUIDE.md)，阶段验收边界见[阶段6报告](PHASE-06-DELIVERY.md)。
