# P2-C-R2 辅助程序挂起调查（技术结论，未实施）

日期：2026-10-30。范围：当前有限 NSIS → Windows PowerShell → C# 安装保护程序。R1 仅修复安装元数据，未增加超时、取消或进程终止代码。P2-B 自动连接恢复仍未完成；不进入 P2-D、Phase 3。

## 结论与证据边界

当前实现不能证明辅助程序在任意挂起点都能安全中止，因此**不建议直接给 `nsExec::ExecToStack` 增加超时后返回或强制结束逻辑**。15 秒暂停后仍等待，只说明该观察窗口内没有独立完成，既不是无限挂起证明，也不是已批准的产品超时阈值。`ps-hang` 保留为未通过/有界恢复未完成。

NSIS 官方说明：`nsExec /TIMEOUT` 是等待输出的空闲时间，收到输出会重置计时，并非整个事务的绝对时限；它返回 `timeout` 也不能单独证明本项目事务已回滚、子进程已退出或文件已释放。[nsExec 文档](https://nsis.sourceforge.io/NsExec_plug-in)。

Windows 在进程结束时关闭其内核对象句柄，但强制终止不执行常规终止处理，而且父进程结束不自动结束所有子进程。因此不能把“已发出终止请求”当作文件恢复成功，也不能把外层 NSIS 已退出当作辅助进程已停止修改。[Windows 进程终止说明](https://learn.microsoft.com/en-us/windows/win32/procthread/terminating-a-process)。

## 各阶段可能持有的资源

| 阶段 | 当前资源与磁盘状态 | 能否只凭时间安全中止 |
|---|---|---|
| PowerShell 启动、Add-Type 编译 | C# 事务尚未进入；可能有编译临时文件或编译子进程。此时尚无本轮五文件组独占句柄 | 仍需确认目标辅助进程、子进程及确实尚未进入事务；不能只按进程名判断 |
| 根目录及串行锁、五文件组预检 | 持有目录身份句柄、串行锁和逐个取得的独占文件句柄；缺失文件可能已创建临时空占位。旧字节未替换不等于没有锁或没有新增文件 | 不安全；必须释放句柄并撤销占位 |
| 元数据准备、备份、journal 落盘 | R1 还持有本产品目标快捷方式的独占句柄，可能创建缺失快捷方式占位；五文件备份逐一校验，journal 序列化并 flush | 不安全；目录存在但 journal 未完整保存时，当前策略是保留并停止，不能盲目重放 |
| 程序替换/卸载及元数据应用 | 全组句柄仍持有；文件可能已截断、写入或标记关闭时删除；注册值可能只写入一部分 | 不安全；终止可能释放锁并落实删除，留下中间状态 |
| 自动回滚或显式 rollback | 持有全组及快捷方式句柄，可能正在恢复不同大小的文件、ACL、时间和本产品注册值 | 不安全；强制结束会中断恢复本身 |
| helper 返回至 NSIS，等待 finalize | 已释放本次句柄，但事务目录仍存在；R1 journal 包含 before/planned-after 元数据；三程序业务入口受屏障保护 | 不能据此清理屏障；必须核对完整组及元数据后完成 finalize 或明确恢复 |
| finalize | 校验文件组和元数据，之后清理恢复资料。这里的文件读取并非全组独占事务 | 不应强杀或并发另启恢复；中断可能留下须人工检查的清理状态 |

依据：`InstallGuard.cs::Run`、`MetadataTransaction::Prepare/Apply/Rollback/Dispose`、`install-guard.ps1` 和 `installer-hooks.nsh`。这些是源码结论；本轮没有把每个阶段都暂停并终止的穷举证据。

## 当前状态辨别能力

- `.in-line-install.lock` 和进程身份可表明有操作正在进行；**锁文件路径存在与否不是可靠的完成或进度标志**，必须核对实际句柄/进程。
- 事务目录及 `journal.xml` 提供固定五文件 before/after、校验过的备份、R1 快捷方式原字节及本产品注册状态。可用来核对磁盘，但它不是持久化的逐阶段状态机。
- `mutated`、`prepared`、`completed` 等目前是进程内变量；NSIS 外部不能仅靠它们判断正在写入还是正在回滚。
- journal 是事前计划；不能把其 planned-after 当作磁盘已经达到该状态。当前恢复对文件及快捷方式并发变化采取拒绝覆盖、保留证据和屏障的策略。
- 文件/快捷方式回滚与注册表写入不构成 Windows 跨资源原子事务。拒绝恢复或异常中断时，必须明确报告“恢复未确认”，不能把安全停止表述为全盘回滚成功。

## 可供另行确认的最小技术路线

1. **先约定产品超时语义**：区分启动/编译、预检/备份、修改、恢复、完成确认；观察超时仅显示“仍在处理/需要检查”，不能当作已安全取消。
2. 若要实现有界等待，优先在现有有限父子进程内增加受控进程句柄、创建时间/路径核对及本轮操作标识，并设计仅本次操作可访问的取消信号和确认回执。不新增常驻中转或接管既有客户端。
3. C# 只在可恢复的安全点接收取消：停止后续修改，在仍持有原句柄和备份时执行/验证回滚，再释放句柄、确认退出。写入、flush、COM 或内核 I/O 本身卡住时，不能承诺有限时刻一定响应取消。
4. 超时后由父进程先请求协作停止并继续等待确认。只有已证明“尚未修改且可撤销全部准备状态”，才可讨论结束该本轮辅助进程；修改或回滚中不得简单强杀。任何结束机制还须证明编译子进程/后代不会继续运行。
5. 不允许 NSIS 先退出失败而 helper 继续写文件。若无法确认停止，则保持受控等待并显示原因；若 NSIS 本身被异常结束，必须保留未完成事务屏障，后续启动/安装拒绝使用中间状态。自动恢复方案须另行验收。
6. 恢复不确定时，保留备份、journal、脱敏的阶段码/Windows 错误码和操作标识；禁止自动删除屏障、跳过检查或再次覆盖。人工恢复必须核对所有目标及并发变更。

该路线有明确限制：在不牺牲数据一致性的前提下，**总耗时硬上限与任意挂起状态必可安全取消，目前不能同时保证**。完整实现需要额外的协议、故障矩阵和验收，等待用户另行确认，不并入 R1。

## 企业策略、编译与异常退出的提示建议

当前包装器编译/执行异常统一返回 3，给出保护程序不可用的泛化说明；正常 Guard 错误返回 1，恢复无法确认可返回 2。NSIS 错误说明应区分：

- 辅助程序未能启动或编译：提示“安装保护程序无法运行，安装已停止；请检查企业 PowerShell/.NET 执行策略或联系管理员”，不把它一概说成文件占用。
- 预检失败：提示精确文件组占用/权限不确定，不终止其他进程。GUI 关闭窗口会隐藏到托盘，应告知通过系统托盘“退出”；独立 MCP 连接还需分别安全释放。
- 已开始修改但恢复未确认：提示勿启动该目录、勿删除恢复资料，并提供脱敏日志位置和支持指引。
- 仍在等待：说明操作尚未被确认取消，不能误导用户再次启动安装器或删除备份。

以上提示分层、持久阶段记录和取消协议均为 **R2 待确认建议**。R1 没有擅自更改执行策略、安装服务、终止任何正式进程或实现超时强杀。企业 AppLocker/WDAC、真实长时 I/O 卡死和异常断电仍未覆盖。
