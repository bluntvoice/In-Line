## 每阶段固定动作

1. 回读三份权威输入、CURRENT_TASK、矩阵与最新用户消息，核对Git及基线变化。
2. 当前阶段内定向实现、隔离验证，保留第一次失败日志；补齐覆盖及负面证据，不能削弱关键测试。
3. 同步README/CHANGELOG/相关PRD/API/错误及迁移文档；尚未开发的功能只写草案，不在公开文档宣称可用。
4. 每阶段运行 npm.cmd test、npm.cmd run build、cargo fmt --manifest-path src-tauri/Cargo.toml -- --check、cargo test --locked --manifest-path src-tauri/Cargo.toml；高风险阶段补本地隔离NSIS及安装升级/旧数据。
5. 完成 `acceptance/PHASE-XX.md`，列未执行/失败/限制、影响及下一步；请求用户验收并停止。需要安装Artifact时遵循用户当时单独授权，不将“做测试”等同正式Release。
6. 收到明确“验收通过，可以提交并推送，进入下一阶段”后，复核范围→指定文件add→Commit→Push→核对远端SHA→检查最新Tag触发规则→固定annotated阶段Tag→推送Tag→报告SHA/Tag，再进入下一阶段。

阶段Tag使用 `mcp-phase-00-accepted` … `mcp-phase-09-accepted`，指向该阶段验收后确定的Commit，不移动/重用；目前release.yml只匹配v*，这些Tag不触发Release。每次打Tag前仍重新核验workflow，不能把P0检查当永久保证。正式SemVer Tag/Release另获批准。
