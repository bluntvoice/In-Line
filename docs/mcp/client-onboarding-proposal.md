# MCP 客户端接入流程调整方案

日期：2026-10-10。状态：用户已确认A（严格无需额外操作），随后明确选择先实现软件内流程并做隔离测试，再验Codex重载。客户端选择、安全提示词与本地导入器已进入本地实现；自动接入入口仍关闭。仍属P1，不代表P1验收通过。

## 需求来源

最新用户要求：“用户选择好ai客户端，点击授予的权限，然后就复制提示词给ai客户端就能实现一键导入，不需要额外操作或输入信息”。

这明确要求将现有“复制JSON配置、手动填写ID/Token、编辑配置”的过程改为由用户主动发起的自动接入。原144项决定和输入副本不改写；采用方案后同步开发PRD、MCP-044追踪、连接指南和验收报告。

## 用户操作

1. 选择AI客户端。
2. 勾选授予的权限；常规读取默认开启，完整读取/写入默认关闭，实际权限仍受全局开关限制。部门/类型范围保留在可折叠的高级选项内。
3. 点击“授权并复制接入提示词”，将提示词发送给所选客户端。
4. AI执行导入并反馈结果。用户不填写客户端名称、ID、Token、安装目录、配置路径或命令；名称默认按所选客户端生成，重复授权保持独立身份。

用户点击授权仍是创建授权的唯一入口。AI执行导入只配置已授权的身份，不增权、不解除暂停、不轮换或撤销其他身份。

## 安全传递与导入

- 提示词不携带长期Token或凭证JSON。软件在独立安全存储域生成本机临时导入包，使用当前用户DPAPI和受保护ACL，绑定机器、Windows用户、指定客户端和授权身份。
- 拟定10分钟有效期、单次消费，过期或成功后失效；失败重试及崩溃恢复需设计确定状态，不能用无限重试重新授权。仅在用户发起授权/复制时生成导入包，不新增匿名业务工具或外网服务。
- 提示词携带已安装导入程序路径和临时包定位信息，要求AI调用软件的导入命令。凭证在本机导入程序内处理，不读取或回显到AI工具输出、启动参数、提示词、日志、Git或业务备份。
- 导入程序按明确选择的客户端适配其用户级MCP配置，只维护In-Line对应条目。已有同名条目先核对程序路径；遇到无关条目/损坏配置/并发变化停止并返回具体原因，不能覆盖整个配置文件。
- 写入前保存受保护配置副本，校验结构并原子替换；ID/Token只进入MCP进程环境配置，不设置系统全局环境或放入命令参数。备份中也可能包含凭据，须放在私有目录并限制保留。
- 用户复制提示词的动作明确发起本次所选客户端配置导入；不扫描或改动未选择的AI客户端。
- 剪贴板写入失败保留本次导入包并允许再次复制，不因重试重复创建客户端。

临时加密导入包已在本轮代码实现，独立授权库仍只保存Token摘要，不能从已保存授权中重建旧Token；再次接入不能悄悄轮换现有凭据。新流程尚未开放，安装与当前会话实机验证独立验收。

## 配置生效和结果

必须分开核验：

1. 导入程序使用写入的配置启动真实stdio子进程，执行`get_capabilities`，检查身份、权限和版本；这是配置与授权连接验证。
2. 所选AI客户端重新加载配置，并在当前会话调用`get_capabilities`；这是当前会话可用验证。不能用另起子进程的成功冒充当前会话已更新。

成功状态：“配置已导入，当前会话连接已验证”。若只完成第一步，应明确返回“配置已导入并验证，当前会话等待重新加载”。无认证、暂停、撤销或权限不足均按实际错误反馈，不能自动变更授权。

Codex官方App Server提供`config/mcpServer/reload`，但本机当前工具集中未发现可直接操作当前应用连接的重载工具；独立启动另一个App Server不能替代刷新当前会话。需验证所支持版本的真实调用入口。[官方App Server](https://learn.chatgpt.com/docs/app-server)

Codex的stdio配置支持`env`，默认用户配置位于`~/.codex/config.toml`。[官方MCP文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

Cursor官方接入指南要求保存后重启；是否存在可用的动态注册接口，需要按目标版本实测。因此不能笼统承诺所有客户端零重连。[官方Cursor接入指南](https://prod.cursor.com/help/customization/mcp)

Claude Code支持用户级MCP配置，用户级服务器储存在`~/.claude.json`；当前会话重载仍需验证。[官方Claude Code MCP文档](https://code.claude.com/docs/en/mcp)

## 已确认的首批范围与门禁结果

用户2026-10-10明确选择：“严格无需额外操作。先验证 Codex，只支持实测能够自动导入并重载的客户端。”不再询问允许重连的B方案。

当前Codex桌面版26.1002.7124.0、CLI0.162.0-alpha.2实测：可回退地写入所选服务器启动配置后，当前会话两次调用未进入新入口，未观察到自动启动或重载探针；探针独立自测通过。当前可调用工具未暴露重载接口，公开CLI控制套接字连接亦失败。原配置已字节一致恢复，没有读取凭据、创建授权或访问业务数据。

结论：当前版本/当前会话未通过零额外操作接入门禁，支持列表暂为空。不能据此承诺所有Codex版本均不可能，也不能把公共API存在或新进程测试冒称现有会话成功。报告见[Codex实机验证](acceptance/CODEX-ONBOARDING-VALIDATION.md)。

最新授权调整了开发顺序：先实现安全导入包、导入器和界面并做隔离测试；自动接入入口仍须当前运行实例重载与身份验证通过后才开放，不要求用户手填或重连。新版Codex26.1007.2314.0/CLI0.162.0-alpha.17.2公开连接通道复测尚未通过。

## 当前实现边界

- 接入包有效期10分钟，当前用户DPAPI与独立ACL，绑定机器/SID/Codex/授权身份。新授权默认命名Codex并保存客户端类型；旧授权类型缺失可正常读取，但不会被静默转成Codex接入。
- 前端只接收packageId/clientId/期限/提示词；长期Token不进入前端或剪贴板。复制失败保留本次提示词；再次复制不会新建或轮换授权。轮换是用户明确点击的独立动作。
- 导入前拒绝暂停/撤销/已轮换身份，核对加密包与路径。现存损坏、同名非In-Line条目、禁用条目、额外启动参数/环境/执行路径设置都停止。只合并用户级mcp_servers.in_line，保留其他设置和服务器。
- 使用独占、进程结束后自动释放的空文件锁协调In-Line导入；提交前和读回核验配置，原配置加密备份，失败只在仍为本次写入内容时回退，保留原字节与ACL。未知结果保持终态，不盲重放。
- 真实stdio验证从已写配置取env，核对当前身份、有效权限交集、范围、授权修订、软件/API版本和工具；仅返回脱敏结果，currentSessionVerified固定为false，不能冒充Codex会话验证。
- 执行开始后接入包单次消费，失败回退亦不复用；中断有attempt记录，没有结果时报告import_in_doubt。未开始写入前的冲突/授权错误不改变配置。再次准备时清理过期未执行包；完成后删除含Token的密文。加密回退/脱敏记录7天后在下一次准备时清理，只删除已知文件，最多保留100个包目录。
- 新界面、后端准备/轮换命令及release导入命令共同执行支持门禁。debug核心与隔离测试可验证流程，正式入口没有开关或配置可绕过门禁；没有新增业务MCP工具或外网监听。

## 实施与验收范围

- 保留当前用户数据库和P1已有实现，不改变事项或业务数据。
- 验证有效/过期/重复消费、伪造或跨用户/机器包、授权撤销/轮换、损坏及并发配置、失败回退、敏感信息无回显、复制失败不重复授权、原stdin/stdout协议无回归。
- 每个客户端用合成配置和独立临时目录测试合并，再做目标客户端实机验收；未选择或未安装的客户端不标记通过。
- 更新P1验收报告及矩阵，再按原门禁等待用户阶段验收。不自动提交、推送、Tag、进入P2或发布。
- 新安装包与本机再安装需基于实现后测试结果安排，不能把已安装的前一P1测试包称为包含本调整。
