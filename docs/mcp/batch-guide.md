# P4 批量与业务文件指南（开发检查点，待 P8 验收）

工具总数为 12：P3 的十个工具，加上 `batch_mutate`、`manage_business_data`。全部要求独立认证；写入还要求常规读取、写入权限及明确用户指令。Codex 自动导入与当前会话重载仍未通过，入口保持关闭。

## 共享业务规则

`mutate_task` 新增 `createSubtask/setParent/reorderSubtasks/queue/reschedule/archive/trash/restore/correctWorkEvent/voidWorkEvent`，使用 GUI 的共享领域事务。队列模式为 `enqueue/reopen/moveUp/moveDown/processRound/completeRound`。办理动作须确认真实办理；纠错与作废须确认历史统计影响。

子任务至多两级，独立状态、日期和号码。未来日期预占号码、延迟入队；旧号码永久不回收。父子或相邻事项实际受影响时，都须在授权范围内。归档和软删除按明确指令执行；不提供永久删除、清空回收站、数据库恢复/覆盖或附件接口。

纠错作废旧记录，追加新记录并用 `correctionOf` 关联。批准撤销同样追加关联更正，不能把旧记录重新改成有效。业务备份合并会重新映射事件编号并保留纠错关联。

## 原子批次

`batch_mutate` 的 `action` 为 `dryRun/apply`，其余参数为 `operations/idempotencyKey/intent/reason/expectedBasis`。每项使用 `operation` 包装一个 `mutate_task` 动作。默认最多 20 项，软件内可改为 1–100；实际涉及的子任务与相邻事项也纳入限额。每客户端每分钟累计最多 200，资源另受 256 KiB 请求上限约束。

预演使用保存点执行同一领域规则后完整回滚，不保留业务信息、字典、号码、审计、幂等回执或数据版本变化。任一事项不确定、越权或不符合规则，整批停止。预演结果按当前权限遮蔽敏感字段，实际执行仍重新验证。

新建项可设 `refKey`，后续使用 `target/parent: {batchRef: "引用名"}`；相应 `taskVersion/parentVersion` 明确传 0。不能引用尚未创建的事项、同时指定另一定位字段或建立第三层。

多事项加入日期或截止时间调整（包括通过 `patch.requestedDeadline` 调整）生成 `needs_user_approval`。用户在设置中审阅整批影响，一次确认后执行；执行时重新核验客户端、权限、范围、每项版本、数据基准和限額。撤销、暂停或并发修改导致冲突时，整批不执行。

实际提交的逐項审计及根批次审计长期保留，原键重复只回读原结果。用户批准批次撤销前核验全部最终状态，然后在同一事务内按逆序执行补偿；保留原历史及号码。提交后核验异常明确报告，不能盲目补写。

## 本地业务文件

`manage_business_data` 的 `action` 为 `backup/export`；都须有写入权限及明确指令。备份固定写入软件备份目录下 `mcp-created`，完整复制业务库，**不包含独立客户端凭证库**。MCP 只返回文件摘要，不能读取、删除或恢复该备份；用户可在软件的备份列表找到它。

导出仅支持 JSON/CSV，采用同一授权查询与冻结分页，最多 10,000 行、32 MiB，固定保存到上述本地目录，不接受自选文件路径。正文等完整字段必须另有完整读取权限；CSV 对可能执行的公式文字进行转义。JSON 附范围、投影和完整性元数据；CSV 是事项表格。

文件创建使用持久作业记录和原键幂等，拒绝覆盖已有目标。响应中断后，仅核验已发布文件并补记完成摘要；有预留记录但无法确认文件时返回 `result_unknown`，不会重新生成。正式文件不属于后续临时缓存。备份/导出不支持业务撤销申请。
