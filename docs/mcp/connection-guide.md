# 2026-10-28 Phase 1 接入说明（未安装、待验收）

在“连接 AI”选择 Codex 后，先选择已有授权身份或明确新增。一个有效身份时默认复用，多个身份不自动猜选。复用不改变权限、范围、全局开关或暂停；需调整权限请到高级管理。已有凭证不能安全核验时停止，由用户明确选择同一身份“轮换并接入”，旧凭证立即失效。不会自动创建替代身份，也不从旧包或不明确的宿主绑定取得复用凭证；签发仍沿用既有过期包维护，不从旧包恢复授权。

复制失败只重试复制；回执过期或点击重新准备后，对已有身份签发新的短期一次性包。不要再次执行旧指令。等价配置回读/独立 stdio 验证后不重写配置文件；安全的用户超时、工具选择和审批策略原样保留。未知/不安全配置仍报告原因并停止。

状态应分别读：`configurationVerified` 说明配置/内部验证通过，`configurationChanged` 说明本次是否替换过配置；导入器不能确认当前线程，因此 `currentSessionVerified=false`。当前会话必须通过原对话挂载调用比对身份/权限/范围。能力响应 `verificationScope=thisToolCall` 只证明该次调用，`credentialResolution.source=currentCredentials` 表示保留当前凭证，`runtimeBinding` 表示应用绑定；`changed` 单独表示凭证值是否变化。`currentCredentials` 可来自初始环境或以前已应用的绑定，不表示一定来自环境。

兼容字段 `sessionCredentialsRefreshed`、`currentSessionAutoImportVerified` 暂时保留原含义并弃用：它们只表示本次应用绑定，同值重复应用仍可为 true，不能证明自动接入/恢复。调用方应改读精确事实，不能把服务端 bool 当作当前线程证明。自动恢复未验证，留待 Phase 2。旧接口参数、工具数及安全边界不变；本阶段没有安装或更新当前运行环境。详见 [验收报告](../MCP_PHASE1_ACCEPTANCE.md)。以下是历史记录。

## 软件内接入流程

当前源码已准备客户端选择、安全提示词和本地导入器；Codex当前会话自动重载尚未通过实机门禁，授权并复制入口暂未开放。当前已安装的上一P1测试包不包含本轮调整。

开放后的用户流程只有：设置中选择客户端 → 勾选权限 → 授权并复制提示词 → 发送给所选AI。名称自动生成，无需输入安装路径、配置路径、ID或Token。长期凭证不进入提示词、剪贴板、启动参数或系统环境；由本机导入程序写入选定客户端的MCP进程env。

常规读取默认开，完整读取/日常写入默认关；有效权限取全局与客户端交集。部门/类型范围收在高级选项，两个条件同时满足，多部门事项须全部获授权；缺部门旧记录不能匹配受限部门范围。没有写入工具，启用权限组也不会新增工具。

提示词10分钟内有效。复制失败使用“再次复制”，不会重复授权；开始执行后单次消费。导入冲突或中断返回真实状态，不自动增权、解除暂停或重放。轮换须由用户明确点击，立即使旧凭证失效；撤销与全局暂停继续优先。

配置已导入并通过真实stdio验证，仍只表示configurationVerified=true；当前AI会话实际核对clientId/有效权限/范围后才能判断currentSessionVerified。不能用另一实例冒充当前会话。未验证客户端不进入支持名单，不以手填或重连作为降级要求。

本轮隔离实现与证据见[验收报告](acceptance/CLIENT-ONBOARDING-LOCAL.md)，当前重载问题见[Codex验证](acceptance/CODEX-ONBOARDING-VALIDATION.md)。

## 旧接口的有意变化

工具名称`get_report_summary`和`list_report_items`保留，业务统计算法复用UI。所有工具含`get_capabilities`都需认证；缺失环境凭证返回`unauthenticated`，不会自动授权或迁移数据库。

- 返回壳为`{apiVersion,requestId,status,data,error}`，原`statistics`/`page`字段现在在`data`内。
- 每页1–100，默认100；超过上限或负offset明确拒绝，不静默截断。
- 报表范围仍最多371天；全历史与稳定跨页快照由P2实现，不声称P1已具备。
- 常规读取保留有效办理结果/时间；自由文本`workEvents.note`为空并标识`redactedFields`。只有全局和客户端均启用完整读取才返回该自由文本，仍不返回联系人、正文或内部备注专用字段。
- 未认证、撤销、暂停、权限不足、限流、版本不兼容、服务不可用分别报告；不把底层路径/SQL/堆栈返回AI。

## 本地存储和测试边界

授权位于Windows当前用户LocalAppData下`in-line-mcp-security/authorization.dpapi`；DPAPI加密、用户专属受保护ACL、明确机器与SID绑定。不纳入业务数据库、业务备份、恢复、缓存或业务导出；不手工复制授权目录。磁盘缓存不加密的决定不适用于凭证。

sidecar只stdio，主程序内部使用仅当前登录会话可访问、拒绝远程的Named Pipe。发送凭证前验证主程序路径和挑战证明；每次由主程序重新鉴权并执行范围过滤。无HTTP/TCP监听。

仅debug编译支持`IN_LINE_MCP_TEST_SECURITY_ROOT`、`IN_LINE_MCP_TEST_DATA_ROOT`和`IN_LINE_MCP_TEST_HOST_EXE`，用于隔离真实主程序/stdio测试；release忽略这些变量。测试标识、WebView目录与业务目录隔离，测试只结束自身管道对应PID，不关闭已安装软件。

P1不执行事项写入、任务恢复、缓存、诊断导出或P2查询扩展。后续按已验收的C1–C4方案实施；正式发布单独验收和授权。
