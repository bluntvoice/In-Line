# In Line 子任务功能 PRD

## 1. 产品目标

子任务是“具有父任务归属关系的完整 Task”，不是 Checklist、附属文本或另一套任务模型。父子关系用于回答“这个任务属于哪一件更大的事情”，队列用于回答“这一轮具体准备处理什么”，两者必须解耦。

除父子归属和少量结构化交互外，子任务继续复用普通事项的状态、排队、编号、截止时间、加急、部门 / 团队、对接人、历史、归档、回收站、搜索、统计、右键菜单和详情能力。

## 2. 数据模型与层级

数据库 schema v8 在 `tasks` 上增加：

- `parent_task_id`：可空的 `tasks.id` 自引用外键，父任务永久删除时 `ON DELETE SET NULL`；
- `subtask_sort_order`：子任务在同一父任务内部的显示顺序，不代表队列顺序。

现有历史事项升级后统一为 `parent_task_id = NULL`，不改变原有状态、队列、编号、时间、归档、回收站、日志或统计数据。

首版只允许两级：

```text
父任务
├─ 子任务
├─ 子任务
└─ 子任务
```

UI 候选过滤和领域层事务必须同时阻止：自指、循环、子任务继续作为父任务、已有子任务的事项再成为子任务，以及任何三级或更深结构。底层采用自引用字段，以免明显阻碍未来扩展，但首版不得开放更深层级。

合法父任务候选为未进入回收站的顶层事项；已完成或已归档但仍存在的顶层事项可以作为候选并显示状态。当前事项自身和任何非法候选不得出现在列表中。

## 3. 关系操作

普通事项可设置所属任务；子任务可查看、更换或解除所属任务。设置、更换和解除时：

- 只更新父子关系、内部排序和必要的 `updated_at`；
- 追加一条普通 `relation` 审计日志；
- 不改写已有日志、状态历史或办理记录；
- 不改变状态、队列、队列编号、排队时间、截止时间、加急、部门 / 团队、对接人或统计记录。

父任务详情支持调整同一父任务下的子任务顺序。该顺序只用于父任务详情和子任务悬浮窗，不得改变今日队列顺序、编号或入队时间。

## 4. 状态与排队

父任务和子任务状态完全独立。父任务完成、子任务完成或全部子任务完成，都不得自动修改其他事项状态。

完成仍有未完成子任务的父任务时，提供“仅完成父任务”“同时完成全部子任务”“取消”。批量完成只处理有效的非终态子任务；已完成、已归档、已取消和回收站子任务不处理，暂缓但仍有效的子任务可以完成。

最后一个未完成子任务完成后，只显示轻量提示“所有子任务均已完成”和“完成父任务”快捷操作，不弹模态窗口、不自动完成父任务。所有完成操作必须复用现有状态、历史和办理记录机制。

父任务和每个子任务都可独立入队并取得各自编号。父任务入队不带入子任务，子任务入队不要求父任务入队。父子结构不得改变真实排队顺序，也不得触发重新取号。

## 5. 创建与属性

新建子任务统一复用一套“轻量创建 + 更多设置”组件，入口包括：

1. 父任务右键“添加子任务”；
2. 父任务详情“添加子任务”；
3. 子任务进度悬浮窗“添加子任务”。

默认突出名称和已确定的所属父任务。“更多设置”可编辑普通事项创建阶段适合的字段。

- 部门 / 团队、对接人在创建时默认复制父任务，创建后双方独立；
- 截止时间和加急默认不继承，父任务后续修改也不影响子任务；
- “立即加入今日队列”开关默认开启；开启时子任务取得自己的今日编号，关闭时只创建完整 Task 和父子关系；父任务始终不自动入队。

## 6. 展示与交互

队列优先表达执行顺序。子任务名称下增加弱化的父任务第二行，长名称截断并支持查看完整内容；父任务可导航。父任务已归档时显示弱化的“已归档”标签。不得新增长期占用大量横向空间的“所属任务”列。

存在子任务的父任务显示“子任务 2/3”和小型圆环。分母为仍存在且归属于该父任务的子任务数量，分子为当前状态“已完成”或“已处理”的子任务数量。圆环表示子任务已完成或已处理的比例，不表示父任务完成度，100% 也不自动完成父任务；父任务完成范围和“全部子任务已完成”提示仍只按真正的“已完成”状态判断。

点击进度区域打开轻量悬浮窗，用于查看子任务、查看状态、快速完成 / 取消完成、进入详情和添加子任务。完整编辑、更换 / 解除所属、删除和归档等低频操作继续通过详情或右键菜单完成。

父任务详情采用“信息摘要 + 快捷操作”，展示子任务名称、状态、截止时间、加急、是否入队及编号等信息，支持查看、常用状态操作、详情、右键菜单、拖拽排序和添加子任务，不嵌入多套完整编辑器。

## 7. 生命周期规则

- 归档父任务：可选择“归档父任务及已完成子任务”或“仅归档父任务”；仍需处理的子任务默认保留，关系不解除。
- 恢复已归档父任务：只恢复当前父任务，不自动恢复子任务。
- 父任务移入回收站：询问“仅删除父任务”“同时删除全部子任务”“取消”。仅删除时子任务保留并解除所属；同时删除时全部进入回收站且关系保留。
- 从回收站恢复父任务：只恢复当前父任务。以后单独恢复子任务时，如原父任务仍存在，继续保留原关系。
- 永久删除父任务：所有仍存在的活跃、已归档或回收站子任务自动解除所属；其他独立数据不变，不得留下悬空外键。
- 合并父任务：目标是合法顶层事项时，源父任务的子任务按原顺序迁移；目标是子任务或会产生非法层级时阻止合并。

## 8. 搜索、筛选与统计

子任务搜索范围为自身原有可搜索字段加父任务名称。通过父任务名称可命中子任务，但通过子任务自身内容命中时，不自动扩展父任务或兄弟子任务。

现有筛选增加“全部”“普通 / 父任务”“子任务”等任务结构类型。统计展示应区分普通 / 父任务数量与子任务数量；强调真实执行的指标可以包含两者，但必须显示子任务数量或占比，不引入人为权重。

## 9. 备份与兼容

备份导入先完成所有源任务到现库任务的 ID 映射，再用第二遍恢复父子关系，绝不直接复制源数据库 ID。

- 现库已有关系优先，备份只为空关系补充父任务；
- 新补关系仍需通过两级、自指、循环和回收站校验；
- 同一父任务下按备份顺序追加，不能扰动现库已有子任务顺序；
- 恢复关系不改写队列、历史办理或统计数据。

升级和恢复必须继续通过 `integrity_check`、`foreign_key_check`、旧库迁移、新库初始化和失败回滚验证。

## 10. 首版不包含

首版不实现三级及以上层级、无限层级、WBS、任务依赖、前置 / 后置任务、甘特图、子任务权重、父任务真实进度推算、自动完成父任务、父子属性持续同步、关系驱动的队列重排 / 重新取号、复杂批量编辑器或悬浮窗完整编辑器。

本轮不新增复制事项。未来如实现：普通事项正常复制；子任务默认复制到同一父任务；复制带子任务的父任务时询问仅复制父任务或复制整组，整组中新子任务必须归属于新父任务。

## v0.5.0 提前取号关联规则（2026-10-02）

子任务默认继承父任务加入日期；父日期已过去时默认今天。支持独立改期，创建后父子日期互不影响。未来子任务预占目标日期序号，不因“立即加入今日队列”开关而提前形成实际队列。截止时间和加急不继承。
