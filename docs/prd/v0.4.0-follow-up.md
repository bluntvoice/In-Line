## 2. 阶段 1：工作量趋势明细

### 2.1 当前实现与边界

当前工作量趋势按日或自然周展示去重后的有效办理事项总数，而非两条独立状态曲线。保留已有总量、时间粒度、周末补齐、排序、图表导出和周期总数口径，在现有柱状图中增加可区分的“已处理”“已完成”数据入口；其他有效办理结果仍保留在原总量中。

点击对应数据，在统计上下文中展开事项明细，复用“事项类型分布”的明细表、信息字段、关闭方式、空状态和点击事项进入现有详情的行为，不设计另一套详情界面。

### 2.2 数据口径

- 沿用 `task_work_events` 的真实有效历史及既有统计查询；不依据当前事项状态反推。
- 总量仍按时间桶内 taskId 去重，同一事项可在不同日期 / 周分别出现，查询周期顶部总数仍全周期去重。
- 时间桶内有多次办理时，以既有最新有效事件（办理时间及 ID 顺序）决定该桶的最终结果；“已处理”为 `processed`，“已完成”为 `completed`，其他结果按真实状态保留。
- 明细查询与计数共用同一筛选、时区、日期边界、有效记录与去重逻辑。日按当地日期，周按现有自然周；查询首尾桶裁到当前统计范围。
- 明细数量必须等于所点击数字；同一事项一行，不跨桶，不重复。记录作废、事项合并、回收站过滤和历史事项类型归属继续遵守原规则。
- 无数据可展示一致的空状态；异步切换日期或类别不得被旧请求覆盖。

### 2.3 验收

验证日“已处理”和“已完成”分别命中正确集合且计数一致；多日期、自然周、首尾部分周、跨日期边界、同桶重复办理、当前状态已改变、作废记录、零值均正确。事项类型原点击、原总量 / 粒度 / 补齐 / 图表交互和导出不回归。明细风格、字段、关闭和进入事项详情与现有类型明细保持一致。

## 3. 阶段 2：默认横向滚动条

### 3.1 三种状态

- A（必须修复）：未打开事项详情、正常工作窗口、默认或合理可容纳列宽时，少量溢出引起无意义滚动条。
- B（允许滚动）：详情占用空间后，列表宽度不足以容纳 8 列合理最小宽度。
- C（允许滚动）：用户主动加宽并保存的列宽总和明显超过可用宽度。

### 3.2 修复约束

排查实际 DOM / 浏览器布局：容器 viewport、8 列宽度、列头和单元格、列宽恢复、padding、margin、border、ResizeHandle、MinWidth、固定与弹性宽度、纵向滚动条占位、末列右侧留白、浮点尺寸、DPI 和缩放。记录可复现根因和尺寸证据。

修复必须消除不合理 overflow，不能永久隐藏水平滚动条、禁用横向滚动、裁切掩盖溢出、清空或改写保存列宽、删除合理最小宽度、在 B 中强压 8 列，或偷偷压缩 C 的用户布局。字体不降到 12px 以下。

### 3.3 验收

首次 / 默认列宽、详情关闭、正常尺寸、最大化、窗口调整、详情打开再关闭、手动加宽、保存重启、恢复默认、待办 / 暂缓 / 归档切换均正确。可行时验证不同 DPI / 缩放；记录自动布局测量的 viewport、scrollWidth 和实际溢出。A 无无意义滚动，B/C 真正宽度不足时仍可滚动，持久化值不被自动改写。

## 4. 阶段 3：三个列表统一行高

### 4.1 需求与边界

待办队列、暂缓事项、历史归档使用同一基础行高和垂直布局，通过共用表格样式 / 资源解决，不分别维护三个魔法数字。分析普通行和父子结构行、标签、图标、换行、字号和 padding 引起的差异，统一到当前较高、舒展的行高。

保持标题、父任务名称、子任务信息、类型、部门、对接人、状态、日期等原有展示规则。当前父任务名称是标题下的次级第二行，不擅自改变原单行省略 / 完整内容提示规则；如明确存在允许多行的字段，行高必须容纳。不能裁切主要内容或按钮换取一致，也不能制造异常大面积空白。

### 4.2 验收

三个页面普通与父子结构行基础高度一致；状态、图标、按钮垂直居中，长标题和父子信息保持原规则，文字与按钮无上下裁切，较原低行更舒展且符合现有密度。切换页面、调整窗口和重启后稳定。字体切换后须再次回归。

## 5. 阶段 4：软件字体设置

### 5.1 系统来源与性能

通过当前 Windows / Tauri 技术栈枚举实际安装且可使用的字体 Family；包含系统和用户安装字体，不使用固定字体清单，不引入不必要的大型依赖。后台枚举一次、缓存结果；搜索只在本地过滤，不随每个字符重新扫描，也不阻塞启动。

中文 / CJK 字体优先，同组稳定排序，不漏其他字体。优先依据真实字符 / 脚本支持；如技术限制必须近似，使用可维护的元信息规则并在交付说明判断方式，不能用短名单替代枚举。排除不可作为普通文本使用的纯 Symbol 字体。

### 5.2 选择器

在现有设置页新增“软件字体”，显示当前有效字体及默认选项。点击打开与现有设置风格一致的选择器：搜索框、可滚动结果、明确选中状态。支持完整 / 部分名称、中文名称、英文别名、不区分英文大小写；清空搜索恢复完整结果，无匹配时显示空状态。

### 5.3 全局应用与设置

- 选择后立即影响主界面、导航、标题、按钮、设置、事项列表 / 详情、标签、统计、弹窗 / 悬浮窗及其他普通 UI 文本，也覆盖辅助窗口。
- 图标使用现有 SVG；特殊 Symbol / 图形字体和必须专用的控件不被替换。普通文本中显式 monospace 声明须审查，选择字体时遵循全局设置。
- 使用现有 SQLite settings / `set_setting` 机制保存，重启读取；跨窗口使用现有数据变更机制同步。不增加独立配置体系。
- 未选择时保留现有默认字体栈 / 原视觉；“默认”恢复原策略，不固定为开发机某个字体。
- 保存字体在当前系统不存在时，安全回退默认，设置页正确显示实际有效状态；启动不失败、无空白文字、无反复报错。跨设备备份恢复设置也遵循此规则。

### 5.4 验收

枚举实际字体、CJK 优先、其他字体完整、稳定排序、中文 / 英文 / 别名 / 部分 / 大小写搜索、清空恢复、选择 / 当前选中 / 关闭 / 零结果均正常。选择即时全局生效，图标正常，关闭重启后保留，默认恢复正确，缺失字体安全回退。

使用默认、中文、英文、较宽 / 较高字体回归三个列表：行高仍统一，文字无上下裁切，状态标签和按钮居中，合理尺寸下无轻微横向溢出，真正到达最小宽度边界仍允许滚动。详情、统计、设置和辅助窗口布局正常；字体选择器打开和搜索无明显卡顿。
