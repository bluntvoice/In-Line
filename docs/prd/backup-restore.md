# In Line 备份导入与恢复体验 PRD

> **适用项目：In Line｜排着呢**
> **目标版本：0.3.0-beta.1**
> **文档状态：Beta 验证**
> **最后更新：2026-09-07**

## 1. 背景

用户更换电脑后，选择有效的 In Line 数据库备份，但误以为“导入备份”会立即恢复事项。旧流程实际上分为：

1. 把外部 `.db` 文件复制到备份目录；
2. 在备份列表中找到该文件；
3. 点击仅有圆形箭头图标的“合并此备份”；
4. 再回到待办、暂缓或归档页面确认结果。

圆形恢复图标容易被理解为“刷新”。同时，备份列表只显示前 12 项，外部文件复制后又可能保留旧修改时间，使已成功导入的文件排到不可见位置。用户删除全部历史备份后重新操作，才看到数据恢复成功。

本次改造目标是消除“文件已导入但数据没出现”的假失败体验，同时保留现有非破坏性合并和恢复前安全备份机制。

## 2. 产品目标

1. 用户通过一个明确入口完成“选择备份、校验、导入、恢复”。
2. 新导入的备份始终立即可见，不受原文件修改时间和历史备份数量影响。
3. 成功后明确说明恢复结果以及数据所在页面。
4. 失败后明确区分原因，并给出可以直接执行的处理建议。
5. 有现有数据时继续采用非破坏性合并，不要求用户删除现有数据或历史备份。
6. 所有恢复操作继续在本机完成，不上传业务数据。

## 3. 本版本范围

### 3.1 一步导入并恢复

软件设置中的主要入口统一命名为：

> 导入并恢复

用户选择 `.db` 文件后，软件显示一次确认提示；确认后按顺序执行：

1. 文件存在性和扩展名检查；
2. SQLite 完整性检查；
3. In Line 必要表及数据库版本检查；
4. 将外部文件复制到应用备份目录；
5. 自动创建当前数据库的 `before-restore` 安全备份；
6. 将备份内容与当前数据合并；
7. 刷新主界面和备份列表；
8. 在右下角显示结果通知。

用户取消确认时，不复制文件、不修改数据库。

### 3.2 空数据库提示

当当前数据库没有任何待办、暂缓、归档或回收站事项时，备份区域显示：

> 当前数据库为空。选择备份后将自动校验并恢复，恢复前仍会创建安全备份。

空数据库与非空数据库使用同一恢复实现，不建立另一套覆盖逻辑。

### 3.3 非空数据库合并

当前数据库已有数据时：

* 完全相同事项：合并关联记录，不重复创建事项；
* 同名但内容不同：创建带“导入冲突”标识的副本；
* 永久编号或日期序号重复：为导入事项分配可用编号；
* 事项类型：去除首尾空格并按不区分大小写规则归并；
* 软件设置：备份中的有效设置覆盖当前同名设置；
* 任一合并步骤失败：事务回滚，当前事项数据保持不变。

用户不得被要求先删除当前事项或历史备份。

### 3.4 备份列表

* 显示全部可恢复备份，不再静默截断为 12 项；
* 标题旁显示备份总数；
* 新导入备份固定置顶并显示“刚刚导入”标识；
* 外部备份复制为新文件时使用当前导入时间，避免沿用源文件旧修改时间；
* 工具栏按钮命名为“刷新列表”，避免与恢复动作混淆；
* 每条备份使用带文字的“恢复数据”按钮，不再只依赖圆形箭头；
* 删除备份仍必须二次确认。

### 3.5 成功通知

恢复完成后，右下角显示非阻塞通知卡片，至少包含：

* 标题：备份数据已成功导入；
* 新增事项数；
* 合并事项数；
* 冲突保留数；
* 提示数据会按原状态分布在不同页面；
* “查看待办”“查看暂缓”“查看归档”跳转按钮；
* 关闭按钮。

如果存在导入冲突，继续显示冲突复核对话框；成功通知不得替代冲突处理入口。

### 3.6 失败通知

导入或恢复失败后，右下角显示错误通知卡片，至少包含：

* 当前阶段：导入失败，或已导入但恢复失败；
* 后端返回的实际失败原因；
* 与原因匹配的推荐处理方案；
* 如果文件已成功加入备份列表，提供“重试恢复”按钮；
* 明确说明当前数据没有被覆盖或导入文件仍保留在列表中。

推荐处理方案至少覆盖：

| 原因 | 推荐处理 |
| --- | --- |
| 备份来自更高版本 | 升级 In Line 后重试 |
| 备份版本过旧 | 在原版本中完成升级后重新备份 |
| SQLite 校验失败 | 改用另一份手动或自动备份，不删除当前数据 |
| 不是有效 In Line 备份 | 选择完整 `.db`，不要选择 `-wal` 或 `-shm` |
| 文件找不到或无法打开 | 复制到本机普通目录并解除其他程序占用 |
| 数据库正忙 | 关闭其他窗口或占用程序后重试恢复 |
| 未识别错误 | 保留原文件、重启软件并记录错误原因 |

## 4. 安全要求

1. 不得将外部备份直接覆盖 `inline.db`。
2. 合并前必须创建 `before-restore` 备份。
3. 合并必须在事务中执行；失败不得留下部分事项。
4. 导入文件复制完成后必须再次进行完整性校验。
5. 失败通知不得建议用户删除当前数据库或清空全部备份。
6. 原始外部备份不得被修改或删除。
7. 本版本不新增数据库结构迁移。

## 5. 非本版本范围

以下内容不在 `0.3.0-beta.1` 中实现：

* 恢复前逐事项差异预览；
* 永久保存每个备份的“已恢复/未恢复”状态；
* 云端备份或跨设备同步；
* 自动删除手动备份、导入备份或恢复前备份；
* 绕过完整性校验强制恢复；
* 用备份整体覆盖当前数据库。

## 6. 验收标准

### 6.1 空数据库

* 初始为 0 项；
* 选择有效备份并确认后，一次操作完成导入和恢复；
* 导入项置顶并高亮；
* 右下角显示成功通知；
* 各页面事项数量与备份状态一致。

### 6.2 有现有数据

* 无需删除当前数据即可恢复；
* 编号重复不会导致恢复失败；
* 完全相同事项不会重复新增；
* 同名不同内容产生可复核冲突；
* 恢复前生成 `before-restore` 备份；
* 合并后原有事项仍存在。

### 6.3 大量备份历史

* 存在超过 12 条备份时仍显示全部；
* 导入修改时间较早的外部备份时，新导入副本仍置顶；
* 用户不需要删除历史备份或手动刷新才能看到导入项。

### 6.4 失败场景

* 无效文件、损坏文件、高版本文件和数据库占用均显示实际原因；
* 每种已知错误均显示推荐处理方案；
* 恢复阶段失败时可以从通知中重试；
* 失败后当前数据库完整性检查通过。

### 6.5 发布验证

该功能属于备份恢复高风险改动，必须按以下顺序验证：

> 自动化测试 → TypeScript 构建 → Rust 测试 → NSIS 安装包 → 隔离安装/升级 → 空库恢复 → 非空库合并 → Beta Pre-release

Beta 不进入应用内普通更新通道。正式版发布前，必须完成至少一轮真实备份恢复验收。
