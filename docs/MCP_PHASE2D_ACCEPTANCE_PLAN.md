# P2-D 最小验收计划（未启动）

日期：2026-10-30。仅提交计划，等待用户确认。R2 已选择 B、暂缓产品开发；本轮没有触发 Actions、执行 MCP/CLI 接入调用、生成或导入接入包、断开连接、安装软件或修改正式授权。

## 目标与执行边界

分别验证首次接入、身份复用、活跃连接上的配置变化、授权控制、断线后恢复、升级后状态，不能用一个“连接成功”概括全部项目。P2-B 当前桌面实例自动恢复仍未完成，不因隔离连接成功而改判。

优先复用既有 Rust/stdio 集成夹具、CLI、MCP 协议检查和 GitHub-hosted Windows 临时环境。实际执行须在本计划获准后：

- 单元/协议用例使用现有显式临时数据库、安全库、配置路径和 test-only 入口；release 不新增任意业务库路径或凭证覆盖开关。不把修改环境变量当成 Windows 用户 Profile 已隔离的证明。
- 如需运行 release 三程序或真实 NSIS，只在新鲜 GitHub-hosted Windows Job 使用合成数据和独立测试身份。优先 Windows 2025，必要时以 2022 对照，不使用 self-hosted runner，不在办公电脑安装。
- 复用已有包时核对候选 SHA、包 SHA-256、三程序构建身份和载荷，不把不同 Git SHA 的包互相冒称。当前开发基线为 `9868a50`；未来执行时再确认最终完整 SHA。
- 不读取或重用真实客户端凭证、不接入正式 Codex/In-Line、不重放既有一次性接入包。凭证只在夹具私有存储或测试子进程环境内使用，不进入命令行、聊天、日志或 Artifact。
- 只允许断开、撤销、轮换本轮创建的合成身份和连接。若发现实际 Profile、正式授权、已有非夹具连接或不能确认归属的进程，立即停止相关用例并报告；不借用正式连接完成验收。

## 六类独立验收

所有下列用例均为 **未执行**；表中是将来的判定标准。

| 编号 | 最小范围 | 通过证据与保留边界 |
|---|---|---|
| D01 首次 MCP 接入 | 空合成安全库创建一个经明确选择的身份；签发新短期包，导入隔离配置；启动实际测试 sidecar，先查 `get_capabilities`，再读一个已知合成哨兵 | 记录客户端数量/ID、构建身份、配置局部差异、导入回执、实际协议调用。缺/错凭证拒绝。成功仅证明该隔离连接；若要验 Codex 宿主自动加载，还需独立受支持宿主环境和证据 |
| D02 已有身份及凭证复用 | 单一既有身份直接复用；多个身份要求消歧；重复等价导入和重新签发新包不重复创建客户端；缺有效凭证时拒绝自动新建/轮换 | ID、权限、范围及授权存储语义不变，重复导入不重复创建。等价配置保持原文；已消费包不重放，过期包使用可控时钟验证并签发新包。显式同 ID 轮换另列子项，不当作普通复用 |
| D03 连接持续有效时配置变化 | 在同一个夹具 stdio 连接上做等价配置重导入、其他 MCP 配置变化、目标配置路径/凭证相关变化 | 对照连接标识、PID/创建时间及多次调用；已加载进程和磁盘配置分别记录。无必要凭证变化时不能声称发生了刷新；配置改变不能冒称当前宿主已重载。其他 MCP 块、审批策略及格式不被破坏 |
| D04 授权、限域、撤销 | 全局权限与客户端权限交集；读写拒绝路径；范围内/外合成哨兵；撤销后在同一夹具连接再次调用；暂停及显式轮换按既有能力分别记录 | 有效权限不能超过原授权；范围外数据不泄露；撤销后拒绝访问。优先只读及负向调用；若必须验证允许写入，仅对独立合成事项做一次可逆变更并核对审计，不开展 16 工具完整业务矩阵 |
| D05 原连接断开后的恢复 | 仅对夹具连接正常 EOF/关闭传输；记录失效结果；可再建立一条明确的新测试连接 | 旧连接结束与测试驱动重连分开。重建协议连接成功不是当前 Codex 对话自动恢复；当前实例受支持入口仍按既有 P2-A 结论受限，自动恢复继续未完成/受阻，不重复调查已知不可达入口 |
| D06 升级后的连接状态 | 优先复用已有 MCP 文件占用/升级证据；如另获准补测，仅在 runner 测试安装器、旧/新三程序身份、配置及合成授权保留 | 活跃 sidecar 占用目标时安全停止，原夹具连接及非目标实例不受影响；仅在夹具正常释放后升级，再核对新程序和新连接。安装失败后旧连接仍有效、升级后新连接可用、原对话自动恢复是三个独立结论，不能相互替代 |

D02 的轮换、D04 的权限调整/撤销只针对事先标识的测试身份，并核对其他合成客户端不变；不自动开启全局权限、解除暂停、扩大限域或创建多余客户端。失败导入须核对原配置及授权状态，恢复无法确认时保留证据并停止，不盲目重试写操作。

## 状态语义及结果分类

每条记录分别填写：

- `configurationChanged`：配置文件是否变化；`configurationVerified`：配置验证是否成立。
- `credentialResolution.source/changed`：本次凭证解析来源及实际变化；`verificationScope=thisToolCall`：只证明该工具调用。
- 隔离连接的实际调用是否成功、PID/连接是否相同、软件/协议/数据库构建身份。
- `currentSessionVerified` 只能指被明确标识的目标宿主会话；隔离 stdio 调用、独立宿主或配置验证不能据此把当前正式 Codex 会话标成 true。

不使用已弃用的刷新标志推断凭证变化、会话接入或自动恢复。`unauthenticated` 仅证明服务响应并拒绝鉴权，不算成功接入；`import_invalid` 不自动等于过期。冲突、撤销、过期及传输关闭按实际错误分类。

结果使用“通过 / 失败 / 未覆盖 / 受宿主能力限制”，每一项有独立证据。受阻项不能按预期失败冒充通过；尤其 D05 自动恢复及 D06 原宿主恢复不得被新建测试连接的成功覆盖。

## 复用资产与最小执行次序（待批准）

1. 只读核对来源和现有证据，再选受影响的既有用例，避免为无变化部分机械重跑全套。
2. 复用 `src-tauri/tests/mcp_onboarding.rs`：实际 stdio 活连接刷新、身份/权限交集、范围、复用及撤销；相关 `mcp::codex_import::tests`、`runtime_credentials`、`security` 测试补充导入失败及授权状态。测试模块和筛选条件执行前从源码核对，不发明未实现的 CLI 子命令。
3. 复用 `scripts/verify-cli-package.mjs`、`scripts/verify-mcp-contract.mjs` 和 `docs/mcp/verify-release-stdio.mjs`，证明三程序身份、16 工具契约及匿名拒绝；这些不替代有授权的正向接入证据。
4. 按 D01→D02→D03→D04 执行最少隔离协议用例，再单独处理 D05、D06。配置有效但实际测试连接未完成时不得继续声称接入已通过。
5. D06 优先引用 [R1 原生证据](mcp/acceptance/MCP-PHASE2C-R1-20261030-checks.json)的 `mcp-lock`、`upgrade` 等结果；只有存在新差异或未覆盖问题且获准时才补跑原生安装，不重复 `ps-hang` 人为暂停实验。

不新建常驻代理、不使用非公开接管接口、不启动额外 App Server 来替代当前实例验收。若现有隔离资产无法覆盖某项，先记录缺口及最小补充方案，等待确认，不借机扩展产品开发。

## 证据、失败处置及阶段门禁

每个用例保留独立编号、执行状态、精确源码/测试 SHA、程序版本和摘要、环境、合成身份别名、权限/范围快照、连接/PID/创建时间、配置差异摘要、退出码及脱敏结果。需要配置字节对照时只限合成夹具；不上传原始凭证、DPAPI 密文、一次性包或真实数据库。

授权存储仅保留同环境前后相等性证明，不输出 Token 或其散列。一次性包失败不盲目重放；结果未知的写入保持原幂等键核验。所有清理仅针对已确认的本轮夹具；保留失败证据，不清理共享 TEMP 或正式 Profile。

P2-D 完成时提供六项独立结果及限制，交用户确认后才能提交/推送。不能用 D01～D04 的成功抵销 D05/D06 的宿主限制；是否接受某项边界由用户另行决定。P2-D 不等于 Phase 3 的完整 16 工具业务验收，更不等于正式发布。
