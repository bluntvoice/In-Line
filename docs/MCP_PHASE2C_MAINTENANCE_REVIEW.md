## 3. 升级检测现状

[verify-installer-safety.mjs](../scripts/verify-installer-safety.mjs)校验实际安装的 `@tauri-apps/cli` 必须为 2.11.4，并校验模板路径、currentUser 模式、资源/sidecar 清单、禁止名称终止路径及启动屏障标记。`prepare-mcp-sidecar.mjs` 导入它；Tauri 的 beforeBuild/beforeBundle 打包路径会执行。CLI 版本改变时，该路径会失败并要求复核模板。

存在明确覆盖边界：

- 普通 `.github/workflows/ci.yml` 的 npm build/cargo test 路径没有直接运行该脚本；不能声称每次普通 CI 都自动发现 CLI 升级。
- 当前没有自动下载上游模板、比对上游全文或校验定制模板基线摘要；版本号未变时的文本漂移、只升级 Rust Tauri 依赖产生的行为变化，也不由该版本断言完整覆盖。
- lockfile 将当前 CLI 固定在 2.11.4，但 package.json 仍允许版本范围；lockfile 更新后须走上述打包门禁。不能把固定版本检查等同于完整上游差异检查。

建议下一次获准修改构建门禁时，让普通 CI 显式运行现有只读检查，并增加受审查的上游版本/摘要记录。升级时先取得新旧官方模板，比较上游变化，再将本差异逐项迁移并重跑组件、载荷和原生生命周期测试；不要仅改版本字符串使断言通过。本轮仅记录建议，不调整 workflow 或实现。

## 4. 重复检查与可简化性

没有证明可以直接删除而不降低安全性的关键检查：静态模板边界、实际占用文件独占访问、备份完整性、写后哈希、完成/回滚前再核对，分别保护不同阶段；Restart Manager 身份查询只用于诊断，不能替代文件句柄。x86/x64 分别测试也不能互相替代。

维护成本主要来自五文件清单在 NSIS、C# 和构建检查中的多处声明，以及与上游模板保留结构的同步。可在以后增加清单一致性断言，优先避免新配置格式、生成层或常驻服务。未使用的上游 UI/迁移分支是否可删，需要先证明不可达并验证，当前保留上游结构也有利于审查差异。本轮不顺带清理或抽象。

## 5. 企业策略禁止执行时的行为

PowerShell 包装捕获 Add-Type/.NET 编译或 guard 执行异常，输出安全检查不可用并退出 3。NSIS 对非零、无法执行或超时等非成功结果执行停止分支，没有名称终止回退。若是 guard 本身没有启动，不能调用成功的文件组事务；但是否显示足够明确的错误、外部进程被策略中止后的返回状态，仍需真实 NSIS 验证。

当前 nsExec 调用未配置显式超时参数。执行被挂起或编译长时间不返回时，能否有界停止尚未验证；不能把常规非零返回的安全停止扩大为所有策略环境都有界失败。建议先测量并设计有界处置，明确超时时子进程、文件锁和事务状态，不把超时当作允许清理标记或继续安装的条件。

`-ExecutionPolicy Bypass` 不能作为已经通过 AppLocker/WDAC、受限语言模式或 .NET 编译策略的证明。当前提示没有区分策略禁止、文件占用和访问拒绝，建议后续提供脱敏分类说明，不提示用户关闭企业安全策略。

需要区分“未替换受管程序”和“安装器完全没有副作用”：SetOutPath 可创建目录，且 WebView2 前置安装 Section 位于 guard 之前，可能先处理系统组件。当前没有对整个 NSIS 进程零副作用的保证；计划优先使用已具备 WebView2 的 VM，缺失前置组件另设快照验证。

## 6. 用户退出与更新可用性

`lib.rs` 主窗口 CloseRequested 会 prevent_close、hide 并显示悬浮窗；托盘菜单“退出”执行 `app.exit(0)`。因此点击窗口 X 后，GUI 仍可能占用文件，安装器正确停止，但用户可能反复重试而无法更新。

应用内现有更新器 `updater.rs` 会启动已校验的安装包，等待 450ms 后请求 app.exit；这不是等待 GUI 已完全退出的确认，也不会释放 Codex 托管的 MCP sidecar。直接双击安装包与应用内更新的行为应分别验收。当前正式更新通道仍只接收正式 Release，不为验收把它改指向开发包。

当前安装提示仅为“请安全退出占用程序后重试”，没有明确说明托盘路径，也没有单独说明 GUI 退出不能释放独立 MCP。建议获准修改时：

1. 指明“系统托盘 → In Line → 退出；关闭主窗口不会退出”，并在托盘图标不可见时说明展开隐藏图标。
2. 明确列出已确认的目标路径/PID，无法确认时直接说明；不要要求按名称结束全部同名进程。
3. MCP 被客户端持有时说明该连接仍占用安装文件；本阶段继续停止，不引导关闭当前正式 Codex 或自动重连，更不能宣称严格自动恢复目标已达成。

这属于后续待确认的提示改进，本轮没有改动安装界面或进程控制代码。

## 7. 文件与安装元数据不一致的风险

已确认文件事务不备份/还原注册表和快捷方式。注册表逐项处理有失败分支，会尝试恢复程序文件组，但可能留下已经写入的新版本注册信息或已删除的卸载项。文件组恢复成功不代表安装元数据恢复成功。

`CreateOrUpdateStartMenuShortcut`、`CreateOrUpdateDesktopShortcut` 的 CreateShortcut/插件调用没有逐项可见的 IfErrors 回滚分支；完成页也可在文件事务 finalize 后创建桌面快捷方式。当前不能保证快捷方式失败一定令安装失败，或在失败后撤销已写元数据。这是原生验收的重点阻断项，不应仅以 NSIS 退出码为 0 判定成功。

正式生成卸载器的自复制行为及自身占用仍未实测。失败/异常中断的恢复，必须同时核对程序组、ARP 注册信息、快捷方式和数据；不能删事务目录来“恢复”。现有 guard 仅在原文、摘要、目录和所有权核对后恢复程序组，不提供完整元数据自动恢复承诺。

当前数据保留策略也保留自启动偏好及 Run 项，卸载后该项可能暂时指向不存在的程序；须记录其对后续登录和重装的影响，不能把有意保留等同所有安装痕迹都清除，也不在本轮擅自改变保留策略。

测试中以 VM 快照作为独立、可靠的实验恢复手段；正式环境若发生元数据不一致，当前实现尚不能据此承诺无需人工的完整恢复。这一点必须在原生验收后单独判定，必要时提出最小元数据备份/恢复方案再获批开发。
