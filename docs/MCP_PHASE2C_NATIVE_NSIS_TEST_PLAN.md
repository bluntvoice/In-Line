# P2-C 原生 NSIS 验收：GitHub 托管 Windows 运行器

日期：2026-10-29（北京时间）。按用户本轮授权，本方案替代独立本地 VM 方案；旧版本保留于 Git 提交 45a778d。允许实现测试资产和执行 GitHub 隔离测试，测试结果仍待用户验收；不在本机安装，不提前推送正式开发分支。

## 1. 环境、权限与来源

使用 GitHub-hosted windows-2025，每个场景独立 Job；windows-2022 运行生命周期兼容性对照。不使用 self-hosted runner，不需要用户配置 VM，不连接正式 Codex/In-Line。[GitHub 官方说明](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job)确认标准 Windows 托管 Job 使用 GitHub 提供的全新环境。

新增独立 [native-nsis-acceptance.yml](../.github/workflows/native-nsis-acceptance.yml)，待审核的正式入口只有 workflow_dispatch。既有 CI、dev-build、Release、版本、更新通道及安装器业务逻辑保持不变。工作流只需 contents/read、actions/read；仓库 Actions 已启用，已验证手动调度接口可用。

为保留验收前不推正式分支的门禁，新增测试资产只推送临时分支 codex/p2c-native-acceptance-20261029。首次登记工作流时，临时快照专用 push 事件只运行登记 Job，不运行安装；原生构建/测试必须由 workflow_dispatch 启动。工作区版本不含该登记事件，临时分支及历史资料不删除。

产品单独 checkout 已提交、验证过的正式开发 SHA 45a778d1646a6b0aded4df606ccc6d72cbac4ced；构建前核对它仍是所选正式开发 HEAD。沿用 npm ci、默认 npm run dist、既有三程序及实际 NSIS 载荷核验。分别记录产品 SHA、测试资产 SHA、运行器镜像及安装器 SHA-256，不能将测试分支 SHA 冒充产品身份。

每次运行应显式填写当时已批准的正式开发 SHA。默认 45a778d 只代表本轮固定基线；以后正式分支改变时不能沿用旧输入绕过 HEAD 核对。

v0.4.0 基线只读下载既有正式 Release，强制核对 SHA-256 f8e0bf5d1ec4ef1c4759579713aa8ca49be05624acd74c50af49a62b30842f68。构建产物通过同一运行的短期 Artifact 传递，各 Job 再次核对摘要与 Commit。不创建 Tag/Release，不替换正式安装程序。

只修改测试资产时，可通过 verified_package_run 复用该工作流此前 package Job 已成功验证的产物，避免重复编译未变产品。必须核对原运行路径/事件、package 成功状态、产品精确 SHA、实际安装包摘要、载荷验证及 v0.4.0 摘要；保留原构建运行和测试运行的独立来源记录。默认仍从正式源码构建，复用不跳过产品身份或安装后的断言。

## 2. 执行安全及证据

[test-native-nsis.ps1](../scripts/test-native-nsis.ps1)强制要求本仓库、GITHUB_ACTIONS=true、RUNNER_ENVIRONMENT=github-hosted 和 Windows；本机误调用会在读取安装包和创建目录之前被拒绝。

测试目录随机生成于 RUNNER_TEMP。开始时确认本产品数据和注册项不存在，发现预存内容则停止。注册表及快捷方式故障只作用于测试产品精确对象，不修改系统 PowerShell 或运行器基础服务。子进程异常退出/暂停只针对本次 NSIS 的明确后代，按父 PID、创建时间、路径及测试目录核对；清理也不按名称结束进程。

所有数据和授权均为合成：有效 SQLite、JSON 偏好、测试用户 DPAPI 加密夹具及含其他 MCP 项的 TOML。GUI 可初始化时，在其真实测试存储中加入合成记录和只读客户端。区分夹具字节保留、实际产品存储验证与完整业务语义，后者不因本轮测试而自动通过。

每次操作保存退出码/超时、安装器及临时卸载副本/辅助进程身份、五文件及旧版程序摘要、注册表 32/64 位视图、快捷方式目标/参数/摘要、数据摘要和事务标记。静默 NSIS 的 stdout/stderr 可能为空，据实标注，不伪称取得内部详细日志。

不上传数据库、DPAPI 原文或密文、Token、完整环境。应用子进程剔除 Token/Secret/Password/Credential 及 In-Line 凭证环境变量。只上传结构化结果和必要脱敏日志，下载 Artifact 的临时凭证只用于下载步骤。

## 3. N01～N15 执行矩阵与边界

下表是执行计划，实际覆盖/结果须以最终 Actions 证据单独填报。

| ID | 原生自动化路径 | 未覆盖或需据实限定的部分 |
|---|---|---|
| N01 全新安装 | 静默运行真实 NSIS；检查文件、ARP、注册目录、快捷方式 | 交互向导显示 |
| N02 跨版本升级 | 实装 v0.4.0，再运行当前开发包，比较旧/新文件和注册版本 | 旧版真实业务迁移；遇不支持主程序名须记录升级受阻，不放宽检查 |
| N03 同版修复 | 完整安装后再次运行同一候选包 | 不代替跨版本升级 |
| N04 GUI 关闭/运行 | 原生 GUI 启动，运行中尝试安装，可取得窗口时请求普通关闭并观察 | 托盘退出 UX、真正正常退出；测试最终清理不得冒称正常退出 |
| N05 MCP 持续占用 | 实际已安装 MCP 保持 stdin；安装/卸载失败；EOF 后重试 | 不连接正式 Codex，不代表自动恢复 |
| N06 正式卸载器 | 真正执行生成的 uninstall.exe；观察自复制进程；另持有原文件测试 | 启动桩退出不代表临时卸载器完成，必须核对最终状态 |
| N07 注册表失败 | 精确 ARP 键拒绝 SetValue/Delete，安装/卸载各尝试两次，恢复测试 ACL 后重试 | 文件与元数据回滚分别判定；外部恢复 ACL 不是产品自动恢复 |
| N08 快捷方式失败 | 精确锁定本产品链接，使创建/更新/删除失败；运行安装、修复及卸载 | 完成页交互回调；返回成功但链接失败应记缺陷 |
| N09 交互取消 | 明确不执行 | 静默流程不能等价替代用户取消，不伪造返回码 |
| N10 异常断电 | 明确不执行 | 不关闭运行器或破坏基础服务，不用辅助进程终止冒充断电 |
| N11 数据/授权保留 | 各成功、失败、修复、卸载、重装前后回读合成 SQLite/JSON/DPAPI/TOML | 实际初始化及授权语义按证据分列，不称业务工具矩阵通过 |
| N12 三程序身份/启动 | 已安装文件哈希；离线身份；原生 GUI 观察；MCP 初始化/工具列表/匿名调用；CLI doctor | GUI 无桌面或初始化失败须单列，不能以离线探针替代 |
| N13 辅助程序故障 | 明确 NSIS 子进程异常退出/线程暂停；私有编译临时目录权限拒绝 | 企业 AppLocker/WDAC、全局禁用未测；等待窗口不证明无限挂起或有界恢复 |
| N14 访问/非目标 | 文件 Write/Delete 拒绝；异目录同名实际 MCP 的 PID/创建时间/字节不变；目标退出后重试 | 第二用户、全部 PID 复用时序及路径别名 |
| N15 前置组件/重试 | 记录 WebView2 与失败后重试 | 不移除既有组件、阻断全局网络或损害基础服务；缺失组件矩阵未测 |

主矩阵为 windows-2025 的 lifecycle、upgrade、file-lock、mcp-lock、uninstaller-lock、file-deny、registry-deny、uninstall-registry-deny、shortcut-deny、ps-exit、ps-compile-deny、ps-hang。windows-2022 仅运行 lifecycle 对照，每个 Job 都使用全新环境。

## 4. 判定、复现与恢复

实际调用 NSIS 安装器/卸载器是必要条件，InstallGuard 组件测试不能代替。文件、注册表、快捷方式、数据和进程必须分别回读：

- 返回 0 但快捷方式失败、文件混合或注册版本错误，不能算安装成功。
- 文件回滚而注册表/快捷方式未恢复，判为恢复未完成。
- 卸载器没有移除完整受管组，不能以启动桩成功冒充卸载完成。
- 只清除测试 ACL/锁后能重试，不等于产品具备元数据自动回滚。
- 原生 GUI 不可用、故障未命中、辅助进程没观察到等，须记部分覆盖/未覆盖或测试资产问题，不误判为已确认产品缺陷。

发现问题保留断言、原值和复现记录，不改产品、降校验或把预期缺陷转为通过。其他独立 Job 可继续；遇必须改产品才能推进的阻断则先报告并等待确认。

测试暂停只使用公开 Windows 线程 API 操作明确的辅助子进程，观察后恢复。超时清理只针对本脚本启动且身份核对一致的进程树；观察窗口和由测试脚本恢复的事实单独记录，不声称产品能自动处理所有挂起。
