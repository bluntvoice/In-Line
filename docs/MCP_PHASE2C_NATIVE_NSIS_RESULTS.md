## 4. 已确认差异、缺陷及复现

### NSIS-NATIVE-01：安装失败后目录记忆值未恢复（策略待确认）

对本测试的 ARP 键拒绝 SetValue，真实安装器均返回 1。五个受管程序回到安装前状态，数据摘要不变；但 HKCU 的 Software\\github\\In Line 默认值新增了本次安装目录，指向已被程序组回滚移除的文件。

同一全新 Job 内，保留第一次失败后，由测试脚本显式恢复自身元数据夹具到相同初始基线，再独立触发第二次，两次相同。重置是外部测试行为，不算产品自动回滚，也没有抹去失败断言。恢复测试键权限后再次安装返回 0。

需要明确其含义：源码 RestorePreviousInstallLocation 会读取此厂商默认值记忆安装路径，正常卸载也保留该值。它不等于 ARP 的“已安装”标记；本次注入未观察到虚假的 ARP DisplayVersion。它确实没有恢复至失败前基线，但是否允许在失败时仍记忆用户选择的路径，应由用户确认策略，不能仅因保留路径就定性为虚假安装成功。严格基线断言仍保留失败，未擅自豁免。证据包括 before-registry-denied-1/2、registry-denied-1/2 的程序/注册/数据差异。

### NSIS-NATIVE-02：卸载注册失败恢复程序，但快捷方式未恢复

完整安装后，对 ARP 键拒绝 Delete，真实卸载体返回 1；原启动桩可返回 0。程序组恢复，ARP 仍存在，合成数据不变，但之前删除的桌面/开始菜单快捷方式没有随程序组恢复。

在相同基线独立复现两次；测试在第二次前恢复原快捷方式字节并核对基线一致，不把这项外部重置称为产品回滚。恢复测试权限后重装可恢复一致状态。该手段证明可重试，不证明产品自动完整恢复。

影响：失败后文件存在但用户入口缺失，卸载/恢复状态不一致。仅看程序哈希或外层进程退出码会漏报。

### NSIS-NATIVE-03：快捷方式失败仍报告成功

精确锁定本产品链接，使写入失败。真实安装及同版修复均返回 0，但链接仍指向合成旧目标，连续两次操作复现。随后保留创建失败证据，另将夹具改成确实指向本安装的有效链接并锁定删除；真实卸载体也返回 0，程序/ARP 已移除，目标链接仍存在。

删除场景不是把保留其他目标的链接误报为缺陷：已单独记录锁定前有效目标及锁定后残留。创建、更新和删除错误没有可靠反映在成功状态中。

影响：系统显示安装/卸载成功，但安装元数据缺失或残留。该失败断言保持为失败，没有把“预期存在缺陷”改成通过。

## 5. 占用保护、卸载器与辅助程序

- 文件句柄占用、Write/Delete 拒绝、实际 MCP 占用及原 uninstall.exe 被持有时，真实安装器/卸载体均返回 1；程序、注册表、快捷方式和合成数据与操作前一致。解除测试条件后安装返回 0，没有部分安装或版本混合。
- 异目录同名的实际 MCP 进程未被结束：PID、创建时间及可执行文件 SHA-256 前后一致；目标 EOF 退出后重试成功时，另一个实例仍在运行。
- 正常实际卸载在 windows-2025 与 windows-2022 都观察到私有临时副本 ~nsu*.tmp/Un.exe；持有该副本进程句柄，用公开 GetExitCodeProcess 取得内层退出 0，五文件移除、ARP 及目标快捷方式清理、数据保留均核对通过。厂商安装路径记忆值按当前模板保留，不宣称所有注册痕迹都删除。原文件被持有时内层为 1，外层启动桩仍可为 0；不能只等待启动桩。
- 实际 NSIS 的辅助 PowerShell 被异常终止或其私有编译临时目录拒绝创建文件时，NSIS 返回 1，未留下部分程序组，清除测试条件后重试成功。编译拒写场景确实观察到本次安装器的 Windows PowerShell 子进程；不把该模拟扩大为企业 AppLocker/WDAC 或全局 .NET 禁用已测。
- 辅助进程暂停 15 秒时，安装器仍等待，没有观察到产品自行结束；由测试脚本恢复线程后安装完成，重试成功。这是受控观察，**15 秒不是已批准的产品超时规格，也不能证明无限挂起**；当前仍未验证有界安全处置。脚本恢复不代表产品自动恢复。

## 7. 最小后续建议与停止点

1. 优先处理两项明确缺陷：为创建/更新/删除快捷方式增加明确错误处理，在卸载失败时与程序组一起恢复本安装受影响的快捷方式。只补退出非零仍不足以保证元数据回滚一致。对安装路径记忆值先确认成功、失败、卸载各场景的保留策略，再决定是否增加有限的注册值备份/恢复，不直接扩成通用注册表事务。
2. 成功条件同时核对程序组与安装元数据；失败后不能把文件组恢复成功写成整体恢复成功。保留已有文件独占、授权、数据保护及未知事务拒绝机制，不引入常驻服务。
3. 对辅助进程有界处置先定义安全取消/等待和事务状态规则，再提出最小实现；不能简单超时放行、按名称结束进程或盲删事务资料。
4. 获准产品修复后，优先复跑失败场景及必要正常回归，继续复用未变来源的验证资产；旧业务库迁移、真实交互、企业策略和异常中断另按范围确认。

本轮只实现测试和记录，尚未修改正式安装器业务逻辑、提交/推送正式开发分支、安装正式环境或创建 Tag/Release。需先由用户验收本报告，再确认产品最小修复范围；不要为了 CI 全绿擅自修产品。P2-B 自动连接恢复继续未完成，不进入 P2-D 或 Phase 3，整个 Phase 2 未完成。
